# onebigbutton · USB 自研版设计草案

日期：2026-11-02；状态：方案草案，尚未画板、选定完整 BOM 或实测。

更新（2026-11-03）：本文件中的 RP2040 / Pico SDK 技术建议已被 CH552G 方案取代。
用户要求保留已放置的 CH552G 和 USB-C 器件，直接在当前嘉立创EDA原理图补外围与连线，器件最终标准化由用户完成。

## 目标与已确认约束

- 单个桌面大按钮，通过 USB 有线连接和供电。
- Windows 11、微信输入法；用户现用 Ctrl + 空格切换。
- 用户选择完整自研 PCB，跳过面包板与现成模块底板。
- 用户熟悉嘉立创打板；源码、文档与可导出的设计资料通过 VS Code/Git 管理。

成功标准是按一次完成一次预期切换，长按不连发，释放后没有模拟按键残留，拔插后恢复。
功能规模较小，但首版仍需验证 USB 枚举、电源、按键事件与机械装配。

## 路线比较

1. 现成 RP2040 模块加底板：外围验证较少，但受模块体积限制。用户未选择。
2. 完整自研 PCB：主控与 USB、电源、按键接口全部集成，结构自由。用户已选择。

以下技术栈和尺寸相关内容为助手建议，不视为用户已经选定的器件或外观。

## 首版技术建议

- RP2040 + 外置 QSPI Flash + 晶振，依据官方最小系统参考设计。
- USB-C，作为 USB 2.0 全速设备与受电端；首版不需要 PD 功率协商。
- Pico SDK + TinyUSB，使用 C/C++ 实现 USB HID 键盘。
- 建议两层 PCB，最终根据实际布局和回流条件复核。
- 建议面板安装的常开自复位大按钮，通过两线端子连接主板，使按钮尺寸与电路板尺寸解耦。
- 首版只有电源/运行指示，不实现准确的中英文状态指示、无线、电池或配置软件。

RP2040 并非单按钮功能的最小成本方案；这里优先考虑资料、工具链与后续可扩展性，不以最低 BOM 成本为目标。

## 硬件功能块

| 模块 | 内容及设计约束 |
| --- | --- |
| 电源 | USB 5V 输入、3.3V 稳压与滤波；RP2040 内核供电及去耦依官方参考 |
| 主控 | RP2040、Flash、晶振与外围；具体型号、封装及参数在原理图阶段核实 |
| USB-C | USB 2.0 数据接口、CC1/CC2 各自的受电下拉、数据线外围和 ESD 保护 |
| 按键 | GPIO 输入、上拉和常开触点；两线端子，固件消抖；不把按钮灯直接接 GPIO |
| 下载恢复 | BOOTSEL、RUN/复位入口和 SWD/GND 调试焊盘，装配后仍可接触 |
| 调试与安装 | 电源和关键信号测试点、固定孔、USB 插拔空间、端子操作空间 |

RP2040 为 QFN 封装。首版建议关键贴片器件采用 SMT 装配，按钮、端子等按实际工艺安装；不假设只靠普通电烙铁即可完成主控装配。
在制作制造资料前，核实嘉立创元件可用性、实际封装、装配方式与预算。
板框、固定孔和 USB 出口位置需在 PCB 布局前结合按钮与外壳确定，当前没有尺寸定案。

## 固件行为

1. USB 枚举完成后进入等待状态；上电时若按钮已按住，先等待释放，避免插线误切换。
2. 按下消抖，建议初始窗口 20 ms，后续依据实物调整。
3. 发送包含 Ctrl 和 Space 的 HID 报告；确认报告已发送后再发送空报告释放本设备的模拟按键。
4. 等待稳定松开后重新允许触发，长按不重复发送。
5. USB 断开、重连和发送失败时重置状态，不重放积压的切换动作。

Ctrl + 空格来自用户当前使用习惯，并非对所有系统和输入法通用的保证。
需验证候选词存在、应用快捷键冲突、另一个键盘同时使用修饰键等场景；出现问题时再决定修改按键序列或配置方式。
设备不根据自身按压次数推断当前中英文状态。

## 软件与文件

- VS Code：编辑、编译、调试与 Git 提交；工具链建议使用官方 Pico 扩展配套环境。
- firmware：主程序、USB 描述符、板级配置、CMake 配置与构建/烧录说明；SDK 和构建产物不直接复制入仓库。
- hardware：嘉立创EDA原理图/PCB可导出源文件、PDF、BOM、装配及制造资料。
- test-results：对应固件提交、硬件版本和实际测试结果。
- software：首版无需电脑端常驻辅助程序。
- 首版使用 BOOTSEL/UF2 下载，SWD 作为可选调试途径。

## 实施顺序

1. 确定大按钮安装形式和主板/外壳约束，核实关键器件与装配资源。
2. 画原理图，复核电源、USB、时钟、Flash、下载恢复和按钮接口。
3. 完成布局布线与 ERC/DRC，复核真实封装、机械与制造资料后打样。
4. 编写固件并完成编译；实板依次验证电源、下载、USB 枚举、按钮事件和输入法切换。
5. 用实测结果修正固件/硬件，完成外壳和使用说明。

## 验证计划

- 板级：电源、BOOTSEL 下载、SWD 可达性、USB 正反插与常用数据线。
- 按键：建议连续 100 次按压逐次核对；长按 5 秒只触发一次；上电按住不触发。
- 系统：Windows 11 + 微信输入法，在 VS Code、浏览器与聊天输入框验证；记录切换实际含义。
- 恢复：拔插、睡眠唤醒、异常发送后无残留按键或自动重复动作。
- 机械：按钮行程、插头与端子空间、固定及防滑。

这些是待执行的检查，当前没有通过实测的结论。
