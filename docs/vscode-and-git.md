# 在 VS Code 中工作与同步

## 打开和阅读

双击根目录的 `idea-lab.code-workspace`。
Markdown 文件按 Ctrl+Shift+V 预览，代码和配置可直接编辑。
根目录就是一个独立 Git 仓库，子项目不要再初始化嵌套仓库。

## 日常提交

1. 在源代码管理中检查修改。
2. 选择需要提交的文件，点击“+”暂存。
3. 输入提交说明，例如“记录按钮尺寸与输入法需求”，点击“提交”。
4. 点击“同步更改”，把本地提交推到 GitHub，并获取远程更新。

首次打开时若 VS Code 提示 GitHub 登录，使用仓库所属账号完成登录。
这里利用 VS Code 自带 Git 功能；未设置定时提交或自动上传。
可通过“终端 → 运行任务 → Git：查看同步状态”检查分支状态。

## 后续项目怎么跑

每个项目独立记录运行命令、工具链与硬件依赖。
软件项目可以按实际语言加入 VS Code 调试或任务配置。
固件需要开发板与烧录工具；原理图和模型用对应工具编辑，保存后照常通过 Git 提交。

## 新增项目

复制 `templates/project` 到 `projects/002-short-name`，修改 README，
再更新 `projects/README.md` 和创意索引。
优先使用英文短目录名，内容和说明可以全部用中文。

## 第三方与公开资料

参考开源项目保留链接和学习笔记；实际引入代码时记录原版本与许可证。
本地环境配置用忽略的 `.env` 等文件；可分享的字段示例用 `.env.example`。
